# Практическая работа № 6. Синхронизация

## Цель работы

Воспроизвести и устранить состояние гонки, применить мьютексы, семафоры и условные переменные, реализовать задачу «производитель–потребитель» и собственный барьер.

## Условия эксперимента

- ОС: Ubuntu Linux
- Python: CPython 3.14
- Логических ядер: 4
- Размер кольцевого буфера: 5
- Производителей: 3
- Потребителей: 2
- Элементов: 1000
- `queue.Queue` не используется

## Проверяемые инварианты

Корректность проверяется программно:

- значение `count` всегда находится в диапазоне от 0 до 5;
- число занятых ячеек совпадает с `count`;
- производитель не перезаписывает занятую ячейку;
- потребитель не читает пустую ячейку;
- после завершения буфер пуст;
- каждый элемент от 0 до 999 потреблён ровно один раз;
- пропущенных и дублированных элементов нет.

## 1. Версия без синхронизации

Файл `race_buffer.py` выполняет операции над кольцевым буфером без блокировок. Между отдельными операциями добавлены точки переключения потоков, чтобы воспроизводить опасные чередования.

Пример результата:

| Проверка | Результат |
|---|---:|
| Создано элементов | 1000 |
| Получено записей | 592 |
| Пропущено элементов | 562 |
| Дубликатов | 154 |
| Диапазон count | −1…8 |
| Нарушений | 1014 |
| Каждый элемент ровно один раз | False |
| Инварианты соблюдены | False |

В разных запусках значения менялись. Наблюдались перезапись занятых ячеек, чтение пустых ячеек, переполнение и отрицательный счётчик. Это подтверждает наличие состояния гонки.

Причина: проверка состояния, изменение ячейки, индекса и счётчика состоят из нескольких операций. GIL не превращает всю последовательность в одну атомарную критическую секцию.

## 2. Семафоры и мьютекс

Файл `semaphore_buffer.py` использует:

- семафор `empty`, начальное значение 5 — количество свободных ячеек;
- семафор `full`, начальное значение 0 — количество готовых элементов;
- мьютекс `mutex` — защита содержимого буфера, индексов и счётчика.

Результат:

| Проверка | Результат |
|---|---:|
| Создано элементов | 1000 |
| Потреблено элементов | 1000 |
| Пропущено | 0 |
| Дубликатов | 0 |
| Осталось в буфере | 0 |
| Диапазон count | 0…5 |
| Нарушений инвариантов | 0 |
| Каждый элемент ровно один раз | True |
| Инварианты соблюдены | True |

Семафор `empty` блокирует производителя при заполненном буфере. Семафор `full` блокирует потребителя при пустом буфере. Мьютекс гарантирует, что структуру буфера одновременно изменяет только один поток.

## 3. Мьютекс и условная переменная

Файл `condition_buffer.py` использует `threading.Condition`, связанную с мьютексом.

Производитель ожидает, пока в буфере появится свободная ячейка:

`while count == size: condition.wait()`

Потребитель ожидает появления элемента:

`while count == 0: condition.wait()`

После изменения состояния вызывается `notify_all()`.

Результат:

| Проверка | Результат |
|---|---:|
| Создано элементов | 1000 |
| Потреблено элементов | 1000 |
| Пропущено | 0 |
| Дубликатов | 0 |
| Осталось в буфере | 0 |
| Диапазон count | 0…5 |
| Нарушений инвариантов | 0 |
| Каждый элемент ровно один раз | True |
| Инварианты соблюдены | True |

`wait()` атомарно освобождает мьютекс и переводит поток в ожидание. Перед возвращением из `wait()` поток снова захватывает этот мьютекс.

## 4. Барьер на условной переменной

Файл `barrier_demo.py` реализует повторно используемый барьер для четырёх потоков и трёх фаз.

Поток после завершения фазы увеличивает счётчик прибывших и ожидает остальные потоки. Последний прибывший поток:

- сбрасывает счётчик;
- увеличивает номер поколения барьера;
- вызывает `notify_all()`.

Поле `generation` не позволяет пробуждённому потоку перепутать разные использования одного барьера.

Результат:

| Фаза | Завершившие потоки |
|---:|---|
| 1 | 0, 1, 2, 3 |
| 2 | 0, 1, 2, 3 |
| 3 | 0, 1, 2, 3 |

Нарушений обнаружено: 0. Все фазы выполнены корректно.

## 5. Ошибка `if` вместо `while`

Файл `lost_wakeup.py` демонстрирует неправильное использование условной переменной.

Опасное чередование:

1. Два потребителя видят пустой буфер и вызывают `wait()`.
2. Производитель добавляет один элемент.
3. `notify_all()` пробуждает обоих потребителей.
4. Первый потребитель захватывает мьютекс и забирает элемент.
5. Второй потребитель получает мьютекс после первого.
6. Из-за `if` он не проверяет условие повторно и читает пустой буфер.
7. Счётчик становится равен −1.

Результат:

| Проверка | Результат |
|---|---:|
| Первый потребитель | получил 42 |
| Второй потребитель | получил None |
| Конечный count | −1 |
| Нарушений | 1 |
| Корректность | False |

При использовании `while` второй потребитель повторно проверил бы `count == 0` и снова перешёл бы в ожидание.

`while` также защищает от ложных пробуждений, которые разрешены семантикой условных переменных.

## Почему критические секции сделаны короткими

Мьютекс защищает только проверку и изменение общего состояния буфера. Создание элементов, обработка полученного значения, задержки и итоговая проверка выполняются вне критической секции. Благодаря этому потоки не превращаются в полностью последовательную программу.

Для автоматического освобождения блокировок используется конструкция `with`.

## Контрольные вопросы

### 1. Чем семафор со значением 1 отличается от мьютекса?

Оба могут ограничить одновременный доступ одним потоком, но назначение различается.

Мьютекс используется для защиты критической секции. Логически освободить его должен поток, который его захватил.

Семафор является счётчиком разрешений и может использоваться не только для взаимного исключения, но и для сигнализации. Один поток может уменьшить счётчик, а другой — увеличить его. Семафор с начальным значением 1 называют бинарным семафором.

### 2. Почему условную переменную нельзя использовать без мьютекса?

Проверка условия и переход в ожидание должны быть атомарными относительно изменения общего состояния другим потоком. Иначе другой поток может изменить состояние и отправить уведомление между проверкой условия и вызовом `wait()`. Уведомление будет потеряно, а ожидающий поток может заснуть навсегда.

Мьютекс также защищает данные, по которым проверяется условие. Метод `wait()` временно освобождает мьютекс, а перед возвратом снова его захватывает.

## Вывод

Состояние гонки возникает, когда несколько потоков без синхронизации изменяют общее состояние. Для ограниченного буфера семафоры удобно представляют число свободных и занятых ячеек. Условная переменная позволяет ждать изменения логического состояния под защитой мьютекса. Проверять условие после пробуждения необходимо циклом `while`. Барьер является ещё одним применением условной переменной и не позволяет потокам перейти к следующей фазе преждевременно.
