2. Скрипт report.sh

Использование:
./report.sh КАТАЛОГ ERROR|WARN [--top N]

Скрипт подсчитывает сообщения выбранного уровня по модулям
и сортирует результат по убыванию количества.
Режим --top N ограничивает вывод первыми N модулями.
Проверяются существование каталога, уровень и значение N.
Без аргументов выводятся справка и код возврата 1.

3. Python и системные вызовы

hello.py читает data/01.log в двоичном режиме
и выводит размер прочитанного содержимого: 19076 байт.
Результат совпал с wc -c.

Трассировка:
strace -f -o trace.txt python3 hello.py

Всего в этом запуске зафиксировано 403 системных вызова.
Служебная строка завершения процесса в подсчёт не включена.

Дополнительная трассировка с -yy позволила определить
операции с data/01.log:
openat — открытие файла;
fstat — получение метаданных;
lseek — запрос текущей позиции;
read — чтение 19076 байт;
read — проверка конца файла, возвращено 0;
close — закрытие файла.

Итого: 6 операций с целевым файлом,
из которых 2 — непосредственно вызовы чтения read.

Остальные вызовы обслуживают запуск программы:
загрузку интерпретатора и библиотек, поиск и чтение модулей,
чтение hello.py, выделение памяти и настройку процесса.
Также сюда относятся вывод результата и завершение.
Поэтому не каждый read в трассировке читает наш журнал.

4. Сравнение с cat

Команда:
strace -f -o trace_cat.txt cat data/01.log > /dev/null

Python: 403 системных вызова.
cat: 139 системных вызовов.
Разница: 264 вызова; у Python примерно в 2,9 раза больше.

Обе программы читают один файл, но выполняют разную работу:
Python вычисляет и печатает размер, cat выводит содержимое,
которое в этом опыте направлено в /dev/null.

В данном запуске Python требует больше системных вызовов
из-за запуска и работы интерпретатора. cat — специализированная
скомпилированная утилита с меньшими накладными расходами.
Число вызовов само по себе не определяет время выполнения.
Результаты зависят от версий программ и окружения.
