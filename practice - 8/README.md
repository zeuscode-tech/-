# Практическая работа № 8. Взаимоблокировки

## Цель работы

Воспроизвести взаимоблокировку, реализовать алгоритм банкира, обнаружение циклов в графе ожидания и способы предотвращения deadlock.

## Среда выполнения

- ОС: Ubuntu Linux
- Язык: Python 3
- Вариант: B

## 1. Алгоритм банкира

Программа `banker.py` загружает:

- вектор доступных ресурсов `Available`;
- матрицу уже выделенных ресурсов `Allocation`;
- матрицу максимальных требований `Max`.

Оставшаяся потребность процесса вычисляется по формуле:

```text
Need = Max - Allocation
```

При проверке безопасности алгоритм ищет процесс, потребность которого не превышает текущий вектор `Work`. После условного завершения процесса его ресурсы возвращаются:

```text
Work = Work + Allocation[i]
```

### Безопасное состояние bank1.txt

Исходный вектор:

```text
Available = (3, 3, 2)
```

Результат:

```text
Состояние безопасное: True
Безопасная последовательность: P1 -> P3 -> P4 -> P2 -> P0
```

Результат совпал с эталоном.

### Небезопасное состояние bank2.txt

Исходный вектор:

```text
Available = (0, 1, 0)
```

Результат:

```text
Состояние безопасное: False
Безопасная последовательность не существует
Не могут завершиться: P1, P3, P4, P2, P0
```

### Обработка запросов

Разрешённый запрос:

```text
request P1 1 0 2
```

Результат:

```text
Запрос принят: True
Запрос разрешён.
```

Небезопасный запрос:

```text
request P4 3 3 0
```

Результат:

```text
Запрос принят: False
Запрос привёл бы к небезопасному состоянию.
Откат выполнен.
```

После отката состояние полностью восстановлено:

```text
Available: [3, 3, 2]
```

## 2. Детектор циклов в графе ожидания

Программа `wait_graph.py` обрабатывает журнал событий:

- `acquire PID RESOURCE`;
- `release PID RESOURCE`;
- `wait PID RESOURCE`.

Если процесс ожидает ресурс, занятый другим процессом, в граф добавляется ребро:

```text
ожидающий процесс -> владелец ресурса
```

Цикл ищется алгоритмом обхода графа в глубину — DFS.

Для журнала `events_deadlock.txt` построен цикл:

```text
P1 -> P2 -> P1
```

Результат:

```text
Взаимоблокировка обнаружена: True
Участники: P1, P2
```

Для `events_safe.txt`:

```text
Граф ожидания: рёбер нет
Взаимоблокировка обнаружена: False
Нарушений журнала: 0
```

## 3. TrackedLock

`TrackedLock` — обёртка над `threading.Lock`, которая отслеживает:

- какой поток владеет каждой блокировкой;
- какую блокировку ожидает каждый поток;
- рёбра графа ожидания.

Перед блокирующим ожиданием выполняется поиск цикла. Если цикл найден, выбрасывается исключение `DeadlockDetected`.

Результат проверки:

```text
Поток-1: захватил Lock-A
Поток-2: захватил Lock-B
Поток-1: ожидает Lock-B, владелец=Поток-2
Поток-2: Обнаружен цикл ожидания:
Поток-1 -> Поток-2 -> Поток-1
```

Оба потока завершились:

```text
Поток-1 завершён: True
Поток-2 завершён: True
Зависших потоков: 0
```

Таким образом, цикл обнаружен до возникновения вечного ожидания.

## 4. Обедающие философы

### Версия с deadlock

В `philosophers_deadlock.py` каждый философ:

1. захватывает левую вилку;
2. ожидает правую вилку.

Все пять философов удерживают по одной вилке и ожидают следующую. Возникает циклическое ожидание.

### Как убедиться, что программа зависла

Программу следует запускать через `timeout`, чтобы она не осталась работать:

```bash
timeout 3s python3 philosophers_deadlock.py
echo $?
```

Полученный код:

```text
124
```

Код `124` означает, что программа не завершилась самостоятельно и была остановлена по тайм-ауту.

В выводе видно, что все философы взяли левую вилку и начали ждать правую.

### Исправление 1: нумерация вилок

Каждый философ сначала захватывает вилку с меньшим номером, затем с большим.

Единый порядок захвата исключает циклическое ожидание.

Результат:

| Философ | Сколько раз поел |
|---:|---:|
| 0 | 100 |
| 1 | 100 |
| 2 | 100 |
| 3 | 100 |
| 4 | 100 |

```text
Всего приёмов пищи: 500
Зависшие потоки: []
Взаимоблокировки нет: True
```

### Исправление 2: ограничение числа философов

Семафор допускает к захвату вилок не более четырёх философов одновременно.

Поэтому все пять философов не могут одновременно удерживать по одной вилке. Хотя бы один философ получает обе вилки, ест и освобождает ресурсы.

Результат:

| Философ | Сколько раз поел |
|---:|---:|
| 0 | 100 |
| 1 | 100 |
| 2 | 100 |
| 3 | 100 |
| 4 | 100 |

```text
Всего приёмов пищи: 500
Зависшие потоки: []
Взаимоблокировки нет: True
```

Задержка `sleep` используется только для моделирования работы. Она не является способом устранения взаимоблокировки.

## Четыре условия возникновения deadlock

Взаимоблокировка возможна, когда одновременно выполняются четыре условия:

1. Взаимное исключение — ресурс используется только одним процессом.
2. Удержание и ожидание — процесс удерживает один ресурс и ожидает другой.
3. Отсутствие принудительного освобождения — ресурс нельзя отобрать.
4. Циклическое ожидание — процессы образуют замкнутый цикл ожидания.

Для предотвращения deadlock достаточно гарантированно нарушить хотя бы одно из этих условий.

## Контрольные вопросы

### Почему упорядочивание захвата ресурсов исключает deadlock?

Если все потоки захватывают ресурсы только в одном глобальном порядке, цикл ожидания построить невозможно. Поток может ждать ресурс с большим номером, но его владелец не будет одновременно ждать ресурс с меньшим номером.

### Почему алгоритм банкира редко применяется в универсальных ОС?

Алгоритму необходимо заранее знать максимальную потребность каждого процесса в ресурсах. В универсальной ОС процессы обычно не могут точно сообщить будущие требования. Кроме того, постоянная проверка безопасности создаёт дополнительные вычислительные расходы и может привести к низкому использованию ресурсов.

`TrackedLock` показал, что deadlock можно обнаружить до блокировки потока. В задаче обедающих философов взаимоблокировка устранена двумя способами: глобальным порядком захвата ресурсов и ограничением числа конкурирующих потоков.
