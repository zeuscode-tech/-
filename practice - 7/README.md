# Практическая работа № 7. Межпроцессное взаимодействие

## Цель работы

Организовать обмен данными между процессами с помощью именованных каналов, Unix-сокетов, Pipe и разделяемой памяти, а затем сравнить эти механизмы.

## Среда выполнения

- ОС: Ubuntu Linux
- Язык: Python 3
- Вариант: B
- Размер массива: 10 000 000 целых чисел
- Объём массива: 38.1 МиБ
- Количество измерений: 3
- Итоговое время: медиана трёх запусков

## 1. Клиент–сервер на именованных каналах FIFO

Сервер использует два именованных канала:

- `request.fifo` — передача запроса от клиента серверу;
- `response.fifo` — передача ответа клиенту.

Примеры выполнения:

```text
Ответ сервера: 2 + 3 * 4 = 14
Ответ сервера: (10 + 5) / 3 = 5.0
Ответ сервера: 2 ** 8 = 256
Ответ сервера: Ошибка: ZeroDivisionError: division by zero
Ответ сервера: Сервер завершает работу
```

Ошибки вычисления обрабатываются сервером и не приводят к его аварийному завершению.

После команды `quit` оба FIFO и временный каталог удаляются.

### Запуск FIFO-сервера

Терминал 1:

```bash
python3 fifo_server.py
```

Терминал 2:

```bash
python3 fifo_client.py "2 + 3 * 4"
python3 fifo_client.py "(10 + 5) / 3"
python3 fifo_client.py quit
```

FIFO обслуживает клиентов по очереди.

## 2. Клиент–сервер на Unix-сокетах

Используется Unix-сокет типа `socket.AF_UNIX`.

Каждое подключение обрабатывается отдельным дочерним процессом, поэтому сервер способен обслуживать несколько клиентов одновременно.

### Запуск Unix-сервера

Терминал 1:

```bash
python3 unix_server.py
```

Терминал 2:

```bash
python3 unix_client.py "100 + 25"
python3 unix_client.py "7 * 8"
python3 unix_client.py "144 / 12"
python3 unix_client.py quit
```

Для одновременного запуска клиентов:

```bash
python3 unix_client.py "100 + 25" &
python3 unix_client.py "7 * 8" &
python3 unix_client.py "144 / 12" &
wait
```

После команды `quit` сервер завершается, а файл сокета удаляется.

## 3. Сравнение Pipe и shared memory

Передавался массив из 10 000 000 четырёхбайтовых целых чисел.

Контрольная сумма:

```text
4995000000
```

Она совпала во всех запусках, поэтому данные были переданы корректно.

| Механизм | Запуск 1 | Запуск 2 | Запуск 3 | Медиана |
|---|---:|---:|---:|---:|
| Pipe | 0.162 с | 0.123 с | 0.115 с | 0.123 с |
| Shared memory | 0.105 с | 0.103 с | 0.103 с | 0.103 с |

Разделяемая память в эксперименте оказалась примерно в **1.20 раза быстрее**.

Pipe копирует данные между адресными пространствами процессов через ядро. При shared memory оба процесса получают доступ к одному сегменту памяти, поэтому лишнее копирование между процессами уменьшается.

## 4. Общая сравнительная таблица

| Механизм | Нужна ли ручная синхронизация | Объём данных | Время |
|---|---|---:|---:|
| FIFO | Да, требуется согласовать открытие и порядок чтения/записи | Небольшие текстовые запросы | Не измерялось |
| Unix-сокет | Сервер должен управлять клиентами; каждый клиент обслуживается отдельным процессом | Небольшие текстовые запросы | Не измерялось |
| Pipe | Основная синхронизация обеспечивается операциями отправки и получения | 38.1 МиБ | 0.123 с |
| Shared memory | Да, использован `multiprocessing.Event`, чтобы читатель не начал работу до записи | 38.1 МиБ | 0.103 с |

## Вывод

FIFO подходит для простого последовательного обмена между локальными процессами. Unix-сокеты удобнее для клиент–серверного взаимодействия и позволяют обслуживать несколько клиентов одновременно.

Pipe прост в использовании, но при передаче большого массива выполняется копирование данных. Shared memory работает быстрее, поскольку процессы обращаются к общей области памяти, однако программист должен самостоятельно обеспечить синхронизацию и удаление сегмента.

## Контрольные вопросы

### 1. Почему разделяемая память — самый быстрый и самый опасный механизм IPC?

Она быстрая, потому что процессы работают с одной областью памяти без постоянного копирования данных через ядро. Она опасна, потому что одновременная несогласованная запись может вызвать состояние гонки и повреждение данных. Поэтому необходимы семафоры, события или другие средства синхронизации.

### 2. Что произойдёт при записи в pipe, у которого закрыты все читающие концы?

Операционная система отправит процессу сигнал `SIGPIPE`. По умолчанию процесс завершится. Если сигнал обработан или проигнорирован, операция записи вернёт ошибку `BrokenPipeError` в Python.
